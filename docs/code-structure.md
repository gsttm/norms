# Code structure

Norms uses TypeScript on Bun. React and Ink provide terminal UI; Ink uses Yoga for layout. The VS Code extension runs on Node's extension host but shares the TypeScript core.

## Packages

| Path | Responsibility |
| --- | --- |
| `packages/core/` | Norm parsing, source resolution, scope and conflict diagnostics, context, and adapters. |
| `packages/cli/` | Command parsing and end-to-end operations. |
| `packages/git/` | Git execution, import sync, repository state, and change context. |
| `packages/providers/` | GitHub and GitLab review adapters. |
| `packages/ui/` | Shared React/Ink terminal output. |
| `packages/vscode/` | Multi-root norm browsing and authoring in VS Code. |

`core` is presentation-independent. The CLI and extension share core APIs and mutation workflows. Provider-specific behavior stays behind `providers`.

## Critical paths

- `packages/cli/src/index.tsx`: CLI entry point.
- `packages/core/src/index.ts`: domain API.
- `packages/vscode/src/extension.ts`: VS Code integration and workflows.
- `install.sh`: checksum-verifying macOS and Linux installer.
- `.norms/norms/meta/`: canonical source for the embedded and cached starter pack.
- `scripts/`: release build and installer verification.
- `.github/workflows/`: cross-platform CI and tagged releases.
- `.norms/`: canonical repository instructions.
- `package.json`, `tsconfig.json`, and `bun.lock`: workspace and toolchain configuration.
- `docs/`: current documentation; `docs/specs/` stores historical contracts.
- `ROADMAP.md`: prioritized future work.

## Generated paths

- `AGENTS.md`, `CLAUDE.md`, `.cursor/rules/norms.mdc`, and `.github/copilot-instructions.md`: tracked adapters generated by `norms sync`.
- `.norms/lock.json`: tracked import resolution generated by `norms sync`.
- `.norms/imports/`: ignored imported checkouts.
- `dist/`, including release binaries, starter pack, VSIX, and checksums, and `packages/vscode/dist/`, including extension tests: ignored builds.
- `.vscode-test/`: ignored VS Code test runtime.
- `node_modules/`: ignored dependencies.

Never edit generated paths when a canonical source exists.
